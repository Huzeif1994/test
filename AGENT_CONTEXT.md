## 🔐 Authentication & Session State Mechanics

To prevent authenticating on every single test, this framework uses **Playwright Setup Projects** that cache sessions into JSON storage states:

```
.auth/
├── ordering.json       <-- Generated by tests/setup/auth.ordering.setup.ts
├── fulfillment.json    <-- Generated by tests/setup/auth.fulfillment.setup.ts
└── admin.json          <-- Generated by tests/setup/auth.admin.setup.ts
```

### Critical Auth Rules:
1. **Never hardcode logins in feature specs:** Tests in `tests/ordering/`, `tests/fulfillment/`, and `tests/admin/` automatically inherit pre-authenticated storage states defined in `playwright.config.ts`.
2. **Multi-App E2E Bridges (`tests/e2e-bridge/`):**
   - E2E bridge tests cross boundaries between Customer and Fulfillment staff in the same spec.
   - Use `browser.newContext({ storageState: '.auth/ordering.json' })` for customer actions.
   - Use `browser.newContext({ storageState: '.auth/fulfillment.json' })` for fulfillment staff actions.

## ⚙️ Frontend Framework (Quasar / Vue SPA) Quirks & Defense Strategies

All three applications use Vue.js and Quasar Framework. Agents must follow these defensive patterns:

### 1. Skeleton Loaders (`.q-skeleton`)
Pages render Quasar skeleton placeholder boxes while data is loading.
* **Rule:** Never interact immediately after navigation. Always wait for `.q-skeleton` to detach:
  ```typescript
  await page.locator('.q-skeleton').first().waitFor({ state: 'detached', timeout: 30000 }).catch(() => {});
  ```

### 2. Backdrop Overlays & Sticky Actions
Sticky action bars or transparent dialog backdrops can intercept clicks.
* **Rule:** When clicking primary buttons (e.g., checkout buttons, modal submit buttons), always scroll into view and use `{ force: true }` if intercepted:
  ```typescript
  await submitButton.scrollIntoViewIfNeeded();
  await submitButton.click({ force: true });
  ```

### 3. Dynamic Masked Inputs
Quasar text inputs (`.q-field__native`) often re-format on keystroke. `fill()` can sometimes preserve leftover characters.
* **Rule:** When entering barcodes, coupons, or phone numbers, clear thoroughly:
  ```typescript
  await input.click();
  await input.press('Control+A');
  await input.press('Backspace');
  await input.fill(value);
  ```

### 4. Brand & Store Dropdown Filter in Fulfillment
Fulfillment searches default to the user's assigned store branch.
* **Rule:** If searching across newly placed orders, select **"All Brands"** from the top brand dropdown before typing the order ID.

### 5. Eventual Consistency Timing
Storefront and Fulfillment use distributed microservices.
* Order sync from Storefront to Fulfillment takes **5–15 seconds**.
* Gift Card activation sync from Fulfillment to Storefront takes **10–20 seconds**.
* **Rule:** Implement polling reload loops (with a max of 5–8 attempts) when waiting for cross-service state transitions.

## 🖥️ Viewport & Browser Standards

* **CI / Headless Mode:** Locked to **1366 × 768** desktop viewport. Launch options include `--window-size=1366,768` and `--no-sandbox`.
* **Headed Mode:** Viewport is set to `null` with launch argument `--start-maximized` to match developer monitors.
* **Global Timeouts:** Test timeout is set to `90_000ms`, `navigationTimeout: 60_000ms`, `actionTimeout: 20_000ms` due to staging environment response latency.

## 🧭 The Mandatory "Step 0: Reconnaissance" Rule

Before authoring code for any new user story or test scenario:
1. **Never guess selectors from HTML intuition.**
2. Probe the live DOM in headless and headed states.
3. Verify Quasar element hierarchy and pseudo-elements.
4. Record findings in `context/annotations/` before finalizing Page Object Models.
